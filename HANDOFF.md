**Cache busting:** scripts are loaded as `i18n.js?v=20261102a` etc. GitHub Pages caches for
about 10 minutes. When you change a JS file, bump the `?v=` on its `<script>` tag. Images aren't
versioned, so **use a new file name** when replacing an image whose name already exists on the live site.

**Reveal system (mirrors the sample's entrance effects):** any element with
`data-r="zoom-down | zoom-up | zoom-out | zoom-in | zoom-tl | zoom-tr | zoom-bl | zoom-br"`
starts hidden and animates in (1.6s) when scrolled into view. `data-delay="300"` staggers it in ms.
Cover elements animate on page load; everything in `#inv` only starts observing after **Open** is clicked.
Corner variants only scale from their corner (no translate), so they stay inside the viewport and the
IntersectionObserver can fire. Keep it that way.

**Continuous motion classes** go on an *inner* wrapper so they don't fight the reveal transform:
`.pulse-l .pulse-r .pulse-tl .pulse-tr` (corner flowers breathing, like the sample's pulse1/pulse2),
`.sway` (hanging vines), `.bob` (characters floating), `.breathe` (wreath/medallion).
Pattern: `<div data-r="zoom-bl"><div class="pulse-l"><img …></div></div>`.
Never put `.bob`/`.sway` on an element that uses `transform: translateX(-50%)` for centring. Centre with
`left:0;right:0;margin:0 auto` instead (already done for `.oval img`, `.cd-pic img`, `.story-hero img`).

**Layout:** a single column of max 430px (`--col`). At ≥960px a fixed scenic panel `.desk` fills the
left (3 crossfading slides + names), and the invitation sits on the right, same as the sample's desktop.

## 12. Invite links: `?to=`, `?s=`, `?lang=`

**Per-language link previews.** WhatsApp/Facebook read `<title>`/`og:*` from the HTML without running JS, so
`?lang=` can't change the preview. `tools/locale-pages.py` writes `ta.html`, `en.html`, `id.html` (copies of
`index.html` with their own title/description/og tags and `data-locale`); GitHub Pages serves them at `/ta`,
`/en`, `/id`. Send guests `https://fer.weds.j6.studio/ta?to=...` (no `&lang=` needed). Never edit those three
files by hand. Old `/?lang=ta` links still work, but show the default (Indonesian/English) preview.

| Param | What it does | Limit |
|---|---|---|
| `to` | Guest name on the cover; also pre-fills the RSVP name | 150 chars |
| `s` | Replaces the salutation line above the name, shown **as written** in every language | 60 chars |
| `lang` | `id`, `en` or `ta`. Forces the page language | |

- Without `s`, the default for the language is used: "Kepada Yth. Bapak/Ibu/Saudara/i", "Dear", "அன்புடையீர்".
- A custom `s` doesn't change when the guest switches language, so match `s` to `lang`.
- Locale order: `?lang=` → page language (`/ta`, `/en`, `/id`) → guest's earlier choice (localStorage) → browser language list → English.
- Over-long values are cut at the last space, else after the last whole letter (`Intl.Segmenter`),
  so Tamil never shows half a letter. Tamil letters like "கு" count as 2+ chars.
- Encode before sending on WhatsApp (plain Tamil/spaces can break the clickable link). Browser console:

```js
'https://fer.weds.j6.studio/?to=' + encodeURIComponent('NAME')
  + '&s=' + encodeURIComponent('SALUTATION') + '&lang=ta'
```

**Rule of thumb:** titles go in `to` with the name (Dato', Dr., திரு.); the courtesy phrase goes in `s`
(Yang Berbahagia, Dear, அன்புடையீர்). Examples:

```
?to=Budi Santoso&s=Kepada Yth. Bapak&lang=id
?to=Dato' Seri Ahmad & Datin Seri Aminah&s=Yang Berbahagia&lang=en
?to=திரு. முருகன் அவர்கள்&s=மதிப்பிற்குரிய&lang=ta
?to=முருகன் குடும்பத்தினர்&s=அன்புள்ள மாமா&lang=ta
```

## 13. Firestore security (`firestore.rules`)

The site is public and the Firebase web config (incl. `apiKey`) is visible to everyone. That's normal:
the apiKey only identifies the project. **Security comes entirely from the rules.**

- The rules file is the **whole** ruleset for `rendezvous-now`, including the bkk trip block. Publish it in
  Firebase console → Firestore → Rules (no firebase CLI here). Publishing a partial file would lock out the other app.
- `wishes`: create only (strict schema: field names, types, lengths, `attending` yes/no, guests 0–10,
  `submitted_at` must be the server time). **No reads**: the page doesn't show other guests' wishes (owner's
  request, 3 Nov 2026), so read access was removed. No update, delete.
- `rsvp_contacts`: create only. Phone numbers can't be read through the site or the API; view them in the console.
- If you add a field to the RSVP write in `rsvp.js`, add it to the rules too, or every submit fails.
- `rsvps` (v1/v2 pages) is not allowed; those pages are retired.
- Optional extra: Firebase App Check (reCAPTCHA) to block scripted spam; needs a site key from the console.
